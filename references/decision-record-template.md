# 决策记录（D 编号）模板

> 每次 think-tank 运行收敛后，CEO 终裁输出一份决策记录，存档为决策史。
> 格式对齐公司 decision-log.md 的 D 条目体例；引用历史结论必须标注 D 编号。

```markdown
## D<编号>（<终裁类型>，<日期>；<议题一句话>）

- 任务来源：<谁提的建议 / 哪个 D 的后续 / 什么触发器>。
- 门禁 0：<通过/驳回>——<一句话主题关系>。
- Verdict：<接 / 改 / 驳>——<一句话结论>。
- 三队观点：
  - 红队：<一句话立场>——<最强质疑>。
  - 蓝队：<一句话立场>——<对 Miao 的损益账>。
  - 白队：<一句话立场>——<执行链要点>。
  - 意外视角（<角色>）：<一句话立场>。
- 总协调建议：<裁决书一句话结论>；<真分歧裁决摘要>。
- CEO 终裁：<维持 / 修改 / 推翻>——<终裁理由>。
  - （若修改/推翻：改了什么、为什么改、证据是什么。D15：董事长意见为建议，采纳/驳回均需写理由。）
- 依据：<引用的 D 编号 / 研究报告 / 数据口径>。
- 复盘点：<什么证据出现时重估本决定；复评日期>。
- D279（如有执行项）：改什么 / 验收 / 责任人 / 截止日期。
```

## 填写纪律

1. **Verdict 三选一**：接 / 改 / 驳。"再看看""待定"不是 verdict，打回重议。
2. **每条有依据**：终裁理由必须挂证据或 D 编号引用；"我觉得"不算依据。
3. **红队质疑全回应**：裁决书里红队提了几条，这里就要有几条回应，不许吞。
4. **复盘点必填**：写清触发重估的条件和日期。没有复盘点的决策 = 假设自己永远正确，不许存档。
5. **试运行标注**：skill 自测/ dry-run 产出的记录，标题必须标注 [试运行]，不进正式决策日志，避免污染真实决策史。
